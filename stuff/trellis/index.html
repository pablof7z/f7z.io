Trellis.

A deterministic reconciler for Rust. State changes in; resource commands, output frames, and an auditable receipt out.

Every useful program eventually acts on the world — opens subscriptions, watches files, holds sync windows. That's also where it stops being inspectable: you can dump state and diff it, but the subscription you opened three states ago is invisible, and when the state that justified it goes away, nothing notices. I kept hitting this bug class in long-lived nostr clients, and the conclusion I reached is that the problem isn't discipline, it's architecture: side effects are the one part of software we still run on trust.

Trellis is my refusal to keep doing that. It's a deterministic reconciler for Rust application kernels: state lives in a transactional graph, I/O is forbidden inside it, and every transaction returns plain data — the exact resource commands implied by what changed, output frames, and a receipt that explains why. It's the same instinct as don't-trust-verify — pointed at my own code first.

the shape of the bug it kills

  • followed accounts → relay set → live subscriptions
  • active workspace → visible projects → desired sync windows
  • open files → module graph → affected files → file watchers

Callbacks and subscription handles work until the source set shrinks, a scope closes, permissions are revoked, or a stale status arrives late. Then a resource leaks — silently, unfalsifiably, in production. You cannot assert your way out, because the bug lives in the gap between your state and your side effects. Trellis makes every one of those transitions an explicit, ordered, testable command: your state lives in a transactional graph, side effects never happen inside it, and every committed transaction returns a resource plan, output frames, and a receipt.

what ships with it

  • A full-recompute oracle in the production crate, not the test crate
  • An honest, documented cost model — O(total-state) per transaction, stated as a design consequence, not hidden
  • Shadow mode: run it beside your existing code and compare, before you trust it or delete anything
  • “Leak Duel” — a browser demo, callbacks vs. Trellis, with a chaos slider showing leaked attachments
  • “Flight Recorder” — git blame for side effects

who's running it

  • NMP — first consumer, in shadow-mode equivalence
  • tenex-edge — live surfaces (relay subscriptions, fabric snapshot) reconciled through Trellis

Pre-1.0: the semantics are stable, the names may not be. MIT OR Apache-2.0.
